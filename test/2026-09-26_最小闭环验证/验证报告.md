# 验证报告：VLA 远程推理与动作执行最小闭环

- 验证日期：2026-09-26
- 验证范围：最小闭环（模拟观测/动作），全链路「树莓派 → Windows Relay → Ubuntu VLA」
- 通信协议：WebSocket
- 验证结果：**通过**

## 1. 验证目标

验证 `基于 SecureLink 的 VLA 远程推理与动作执行方案.md` 中的三层架构能否正常工作，具体确认：

1. 连接 A：树莓派能主动连接 Windows Relay；
2. 连接 B：Windows Relay 能主动连接 Ubuntu VLA 服务（经 SecureLink）；
3. 端到端消息链路：观测上传、动作下发、执行 ACK 反馈能双向贯通。

## 2. 架构与网络拓扑

```
树莓派设备端 (pi@192.168.2.30)
      │ 连接 A：树莓派主动连接 ws://192.168.2.49:9443
      ▼
Windows Relay (本机，WLAN 192.168.2.49 / SecureLink 10.30.114.4)
      │ 连接 B：Windows 主动连接 ws://10.0.80.19:8443
      ▼
Ubuntu VLA 服务端 (narwal@10.0.80.19:8443)
```

两端连接均由靠近设备的一侧主动发起，不需要反向建连。

## 3. 验证结果

### 3.1 连接 A TCP 连通性

树莓派 `192.168.2.30` 访问 Windows `192.168.2.49:9443`：

```bash
# 在 Windows 用 Python 监听 9443，树莓派执行：
timeout 5 bash -c "echo > /dev/tcp/192.168.2.49/9443" && echo TCP_OK
```

结果：`TCP_OK`。

> 注意：树莓派 ping Windows（ICMP）不通，是 Windows 防火墙拦截 ICMP 所致，不影响 TCP 长连接。连接 A 使用 TCP，验证通过。

### 3.2 端到端全链路

三端日志完全吻合，循环发送观测/动作/ACK 多轮全部成功。示例链路：

```
树莓派 --观测 seq=1--> Relay [A->B] --> Ubuntu（收到观测，返回动作 seq=1）
树莓派 <--动作 seq=1-- Relay [B->A] <-- Ubuntu
树莓派 --ACK----------> Relay [A->B] --> Ubuntu（收到 ACK status=executed）
```

三端关键日志摘录：

- 树莓派：`发送观测 seq=1` → `收到动作 action_seq=1` → `发送执行 ACK action_seq=1`
- Relay：`[A->B] 转发 type=observation obs_seq=1` → `[B->A] 转发 type=action action_seq=1` → `[A->B] 转发 type=ack action_seq=1`
- Ubuntu：`收到观测 ... seq=1` → `返回动作 action_seq=1` → `收到执行 ACK action_seq=1 status=executed`

## 5. 结论

三层架构的最小闭环验证通过，核心结论：

1. 树莓派无需 SecureLink，只需主动连接本地 Windows Relay；
2. Windows 通过 SecureLink 主动连接 Ubuntu，Ubuntu 在既有连接内返回动作；
3. 观测、动作、ACK 三类消息双向贯通，`device_id`、`session_id`、序号全程保持。
