# 手动验证方法：VLA 与树莓派通讯的延迟与稳定性

本文档提供可复现的手动验证步骤，测量「树莓派 → Windows Relay → Ubuntu VLA」全链路的
延迟（RTT 及其分布、抖动）与稳定性（长跑、断线重连）。

与 `test/2026-09-26_最小闭环验证` 的区别：那份验证「消息能否通」，本份验证
「通了之后延迟多大、能否长时间稳定运行」。

## 0. 前置条件

- 三台主机已配置 SSH 免密访问；
- 三端已安装 Python 3 与 `websockets` 库：
  - Windows 本机：`python -m pip install websockets`
  - 树莓派：`ssh pi@192.168.2.30 "pip3 install --break-system-packages websockets"`
  - Ubuntu：`ssh narwal@10.0.80.19 "pip3 install websockets"`

涉及文件与位置：

| 文件 | 位置 | 作用 |
| ---- | ---- | ---- |
| `vla_server.py` | Ubuntu `~/work/vla/src/vla/server/` | 连接 B 服务端，收到观测即回动作 |
| `relay.py` | Windows 本机 `src/relay/relay.py` | 中继（连接 A 服务端 + 连接 B 客户端） |
| `echo_server.py` | Windows 本机 `test/2026-09-27_延迟与稳定性验证/` | 连接 A 段测延迟用的 echo 服务端 |
| `latency_probe.py` | 本机与树莓派 `~/vla_probe/` | 延迟/稳定性探测客户端 |

## 1. 启动被测链路

必须按「Ubuntu → Windows Relay → echo → 树莓派」顺序启动。

### 1.1 启动 Ubuntu VLA 服务端

```bash
ssh narwal@10.0.80.19 "cd ~/work/vla && setsid nohup python3 src/vla/server/vla_server.py > /tmp/vla_server.log 2>&1 < /dev/null & sleep 2; ss -ltnp | grep 8443"
```

期望输出包含 `LISTEN ... 0.0.0.0:8443`。

### 1.2 启动 Windows Relay

```powershell
cd d:/work/vla_bridge
Start-Process python -ArgumentList 'src/relay/relay.py' -WorkingDirectory 'd:/work/vla_bridge' -RedirectStandardOutput 'd:/work/vla_bridge/_relay.out.log' -RedirectStandardError 'd:/work/vla_bridge/_relay.err.log' -WindowStyle Hidden
```

### 1.3 启动 Windows echo 服务端（仅连接 A 段延迟测试需要）

```powershell
Start-Process python -ArgumentList 'test/2026-09-27_延迟与稳定性验证/echo_server.py' -WorkingDirectory 'd:/work/vla_bridge' -RedirectStandardOutput 'd:/work/vla_bridge/_echo.out.log' -RedirectStandardError 'd:/work/vla_bridge/_echo.err.log' -WindowStyle Hidden
```

### 1.4 部署探测脚本到树莓派

```powershell
scp "d:/work/vla_bridge/test/2026-09-27_延迟与稳定性验证/latency_probe.py" pi@192.168.2.30:/home/pi/vla_probe/latency_probe.py
```

## 2. 延迟测试

`latency_probe.py` 参数：

| 参数 | 说明 |
| ---- | ---- |
| `--uri` | 目标 `ws://` 地址（必填） |
| `--label` | 统计标签 |
| `--mode` | `pingpong`（收到即发下一条，测纯 RTT）/ `interval`（固定间隔，测稳定性） |
| `--duration` | 运行秒数 |
| `--interval` | interval 模式发送间隔（秒） |
| `--timeout` | 单次回包超时（秒） |

### 2.1 连接 B 段延迟（Windows → Ubuntu，经 SecureLink）

在 Windows 本机执行，直连 Ubuntu 服务：

```powershell
cd d:/work/vla_bridge
python test/2026-09-27_延迟与稳定性验证/latency_probe.py --uri ws://10.0.80.19:8443 --label B --mode pingpong --duration 60
```

### 2.2 连接 A 段延迟（树莓派 → Windows，本地网）

在树莓派执行，连 Windows 的 echo 服务（不走 SecureLink）：

```bash
ssh pi@192.168.2.30 "python3 /home/pi/vla_probe/latency_probe.py --uri ws://192.168.2.49:9444 --label A --mode pingpong --duration 60"
```

### 2.3 端到端延迟（树莓派 → Relay → Ubuntu → Relay → 树莓派）

在树莓派执行，连 Windows Relay 的 9443：

```bash
ssh pi@192.168.2.30 "python3 /home/pi/vla_probe/latency_probe.py --uri ws://192.168.2.49:9443 --label E2E --mode pingpong --duration 60"
```

期望关系：`端到端 RTT ≈ 连接 A RTT + 连接 B RTT + Relay 处理开销`。

## 3. 稳定性测试

### 3.1 短时稳定（1Hz 端到端）

```bash
ssh pi@192.168.2.30 "python3 /home/pi/vla_probe/latency_probe.py --uri ws://192.168.2.49:9443 --label E2E-stab --mode interval --interval 1 --duration 300"
```

合格标准：`超时率 0%`、`重连次数 0`。

### 3.2 长时间运行（文档建议 ≥30 分钟）

用于验证 SecureLink、代理或 NAT 是否会清理长时间空闲连接。建议以
`--mode interval --interval 2` 持续运行 30 分钟，期间不允许出现重连：

```bash
ssh pi@192.168.2.30 "nohup python3 /home/pi/vla_probe/latency_probe.py --uri ws://192.168.2.49:9443 --label LONG --mode interval --interval 2 --duration 1800 > /tmp/probe_long.log 2>&1 < /dev/null & echo STARTED"
# 结束后查看：
ssh pi@192.168.2.30 "cat /tmp/probe_long.log"
```

### 3.3 断线自动重连

验证连接 B 中断后系统能感知并恢复。分两条命令执行，避免 `pkill` 误杀自身
（同一行内若同时出现 `pkill -f` 与文件名，会匹配到承载命令的 shell）：

```powershell
# 1) 树莓派启动端到端探测
ssh pi@192.168.2.30 "nohup python3 /home/pi/vla_probe/latency_probe.py --uri ws://192.168.2.49:9443 --label RECONN --mode interval --interval 1 --duration 60 > /tmp/probe_reconn.log 2>&1 < /dev/null & echo STARTED"

# 2) 约 20 秒后，停掉 Ubuntu 服务（注意 [v] 技巧避免匹配自身）
ssh narwal@10.0.80.19 "pkill -f '[v]la_server.py'; sleep 1; ss -ltnp | grep 8443 || echo PORT_FREE"

# 3) 再启动 Ubuntu 服务，模拟恢复
ssh narwal@10.0.80.19 "cd ~/work/vla && setsid nohup python3 src/vla/server/vla_server.py > /tmp/vla_server.log 2>&1 < /dev/null & sleep 2; ss -ltnp | grep 8443"

# 4) 探测结束后读取结果
ssh pi@192.168.2.30 "cat /tmp/probe_reconn.log"
```

合格标准：探测日志出现一次 `连接中断` 后能自动 `已连接` 恢复，重连次数与
中断次数一致，恢复后不再持续失败。

## 4. 判断标准

满足以下条件即为通过：

1. 三段延迟均可测得，且 `端到端 ≈ 连接 A + 连接 B`；
2. 端到端 `p95` 在数十毫秒量级，`超时率` 低（长跑 `< 1%`）；
3. 长跑期间 `重连次数 = 0`；
4. 主动中断连接 B 后能自动重连恢复。

## 5. 停止与清理

```bash
# 树莓派：停止探测与设备客户端
ssh pi@192.168.2.30 "pkill -f '[l]atency_probe.py'; pkill -f '[r]elay_client.py'"

# Ubuntu：停止 VLA 服务
ssh narwal@10.0.80.19 "pkill -f '[v]la_server.py'"
```

```powershell
# Windows：按端口结束 Relay(9443) 与 echo(9444)
Get-NetTCPConnection -LocalPort 9443,9444 -State Listen |

  Select-Object -ExpandProperty OwningProcess -Unique |
  ForEach-Object { Stop-Process -Id $_ -Force }
# 删除临时日志
Remove-Item d:/work/vla_bridge/_relay.*.log,d:/work/vla_bridge/_echo.*.log,d:/work/vla_bridge/_probe*.log -ErrorAction SilentlyContinue
```

## 6. 注意事项与故障排查

| 现象 | 排查方向 |
| ---- | ---- |
| SSH 启动后台服务后命令挂起 | 后台进程继承了 SSH 的 stdout/stderr，需用 `setsid ... < /dev/null` 或重定向所有输出 |
| `pkill` 后 SSH 命令无输出、连接中断 | `pkill -f 关键字` 匹配到了承载命令的 shell 自身，关键字用 `[x]xx` 形式规避 |
| Ubuntu 启动报 `address already in use` | 8443 被占用，先 `pkill -f '[v]la_server.py'` 再启动 |
| Windows 启动报 `WinError 10048` | 9443/9444 被残留进程占用，按第 5 节端口定位命令结束 |
| 连接 B 建立失败 `WinError 1225` | Ubuntu 服务未运行或 SecureLink 策略未放行 `10.0.80.19:8443` |
| 树莓派连不上 Relay | 检查 Windows 防火墙是否放行 9443/9444；使用 `192.168.2.49` 而非 VMware 网卡地址 |
| 延迟数据异常偏大 | 确认测试期间无其他大流量任务，重连刚恢复的瞬间会出现延迟尖峰 |
