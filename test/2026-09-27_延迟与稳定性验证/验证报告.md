# 验证报告：VLA 与树莓派通讯的延迟与稳定性

- 验证日期：2026-09-27
- 验证范围：全链路「树莓派 → Windows Relay → Ubuntu VLA」的延迟与稳定性
- 通信协议：WebSocket
- 验证结果：**通过（满足延迟与稳定性要求，另有需改进项见第 7 节）**

## 1. 验证目标

在 `test/2026-09-26_最小闭环验证` 已确认「消息能通」的基础上，进一步量化：

1. 各段往返延迟（RTT）与分布：连接 A（树莓派↔Windows）、连接 B（Windows↔Ubuntu，经 SecureLink）、端到端；
2. 延迟抖动与超时率；
3. 持续运行的稳定性，以及连接中断后的自动重连能力。

## 2. 架构与网络拓扑

```
树莓派设备端 (pi@192.168.2.30)
      │ 连接 A：ws://192.168.2.49:9443（本地 WiFi）
      ▼
Windows Relay (本机，WLAN 192.168.2.49 / SecureLink 10.30.114.4)
      │ 连接 B：ws://10.0.80.19:8443（经 SecureLink）
      ▼
Ubuntu VLA 服务端 (narwal@10.0.80.19:8443)
```

延迟测量原理：探测客户端发送带序号的 `observation`，服务端立即回 `action`（或
echo），客户端用**同一本机单调时钟**计算往返时间，无需跨端时钟同步。

## 3. 测试方法

| 测试项 | 运行位置 | 目标 | 模式 |
| ---- | ---- | ---- | ---- |
| 连接 A 延迟 | 树莓派 | `ws://192.168.2.49:9444`（echo） | pingpong 15s |
| 连接 B 延迟 | Windows | `ws://10.0.80.19:8443` | pingpong 15s |
| 端到端延迟 | 树莓派 | `ws://192.168.2.49:9443`（Relay） | pingpong 20s |
| 端到端短时稳定 | 树莓派 | Relay | interval 1Hz 60s |
| 端到端长跑稳定 | 树莓派 | Relay | interval 2s 180s |
| 断线重连 | 树莓派 | Relay（中途重启 Ubuntu） | interval 1Hz 60s |

**pingpong**：收到回包立即发下一条，最大化往返频率，测纯 RTT 与抖动。
**interval**：按固定间隔发送，测长期稳定性与超时率。

### 4.5 断线自动重连（中途重启 Ubuntu 服务端）

过程：探测运行约 20 秒时停掉 Ubuntu `vla_server`，数秒后重新拉起。

| 指标 | 值 | 指标 | 值 |
| ---- | ---- | ---- | ---- |
| 样本数 | 57 | p95 | 158.93 ms |
| min | 34.56 ms | p99 | 739.49 ms |
| avg | 98.63 ms | max | **1689.20 ms** |
| p50 | 47.54 ms | 标准差 | 232.43 ms |
| 超时次数 | 2 | 重连次数 | 1 |
| 超时率 | 3.39% | 抖动 | 29.55 ms |

探测日志显示：`连接中断` 后 `2.0s 后重连` 并成功 `已连接`，随后持续稳定。
**结论：系统能感知连接 B 中断并自动重连恢复**；但恢复瞬间出现明显延迟尖峰
（max 1.69 s），恢复后统计被拉高（avg 从 53 ms 升至 98.63 ms）。

## 6. 结论

1. **延迟**：连接 A 中位 3.79 ms，连接 B 中位 25.95 ms，端到端中位约 38～46 ms、
   p95 约 71～92 ms。延迟主要由 SecureLink 段（连接 B）贡献。
2. **抖动**：pingpong 下抖动很小（连接 B 0.39 ms、端到端 0.60 ms），但存在偶发
   尖峰（端到端 max 301 ms）；1Hz 低频下抖动升至约 2.8 ms。
3. **稳定性**：60 秒 1Hz 与 180 秒 2s 端到端运行均零超时、零重连，连接保持稳定。
4. **重连**：连接 B 中断后客户端可通过约 2 秒退避自动重连恢复，恢复瞬间有延迟尖峰。
5. 该延迟水平**不适合电机级闭环控制**，与方案文档结论一致。Ubuntu 只应下发
   高层目标/短动作块（1～20 Hz），实时轨迹插值、限速与碰撞检查留在树莓派本地完成。

## 7. 局限与后续

- 本次为模拟观测/动作，未接入真实相机图像，测试时段网络状况有限，**完整 30 分钟
  长跑与真实图像负载下的延迟仍需补充**（方法见同目录 `手动验证方法.md` 第 3.2 节）；
- 当前 Relay 未实现心跳、背压与**自身**的重连退避：实测当连接 B 后端不可用时，
  Relay 会立即关闭连接 A，树莓派被迫高频重连（观察到约 5 秒一轮、无退避），
  需按方案文档补齐指数退避与断线清理；
- 重连恢复瞬间的延迟尖峰（>1.6 s）提示需要评估 SecureLink 重新协商对实时性的影响；
- 尚未加入 TLS/mTLS、设备认证与过期动作丢弃，后续按方案文档第 10 节实施顺序补全。
